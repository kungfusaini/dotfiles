# System-wide Project Object — Interview Guide

This is a focused interview, not an exhaustive questionnaire. We will ask one broad question at a time, use follow-ups only when necessary, and skip anything already answered naturally.

Status:

- **Answered** — enough direction for now
- **Partial** — discussed, with important details still open
- **Open** — not yet discussed

## Vision

1. **Answered — Ideal experience:** What happens when you choose, enter, work in, and switch away from a project?
2. **Answered — Problems:** Which current problems must the system solve?
3. **Answered — Lessons from the old system:** What should be preserved, and what should not be recreated?
4. **Answered — New capability:** What should become possible that is difficult today?

## Project model

5. **Answered — Definition:** What makes something a project, and what remains outside the project system?
6. **Answered — Scope and identity:** How broad can a project be, what resources can it contain, and what makes it remain the same project over time?
7. **Partial — Projects and streams:** How should projects, streams, substreams, shared context, and context promotion relate?
8. **Answered — Lifecycle:** What should creating, opening, switching, closing, archiving, and deleting a project mean?
9. **Partial — Home and global space:** How should Home, global applications, and unassigned activity relate to projects?

## Context and work

10. **Partial — Durable context:** What information must be remembered so a person or agent can resume a project confidently?
11. **Partial — Worklogs:** What should worklogs record, where should they be visible, and how should project and stream logs roll up?
12. **Partial — Tasks and plans:** How should global tasks, project tasks, stream tasks, plans, and external trackers relate?

## System surfaces

13. **Answered — Desktop:** How should projects map onto Hyprland workspaces, windows, monitors, and application state?
14. **Answered — Global interface:** What should the project picker and persistent system-wide UI show and control?
15. **Partial — Terminals and processes:** What roles should terminal windows, tmux, development services, and remote processes play?
16. **Answered — Agents:** How should main agents, subagents, their context, progress, and hierarchy relate to projects and streams?
17. **Answered — Attention:** How should the system show that an agent needs help without interrupting focused work?

## Boundaries and delivery

18. **Answered — Persistence and portability:** What should survive restarts, what moves between machines, and how should failures be recovered?
19. **Answered — Ownership and independence:** What should the core system own, what should adapters control, and how can it remain tool-independent?
20. **Answered — First useful version:** What is the smallest complete version, what must it include, and how will we know it succeeds?
