Pi orchestrator

Proper worker ownership

A session should only see and control its own workers by default.

Today

Registry is shared. Read/list/status can see everyone.

Target

Shared storage, but session-scoped access and side effects.

Key idea: shared storage is fine; shared permissions are not.
Current model

What exists now

Pi session

The parent session that starts workers.

Worker record

JSON file with state, tmux info, and ownerSessionId.

tmux session

The real terminal process that runs the worker.

Herdr pane

Visible UI surface when a worker is surfaced.

Problem

Why it feels wrong

Global visibility

  • List reads the whole registry.
  • Status also polls the whole registry.
  • Read can inspect other sessions’ workers.

Read paths have side effects

  • Refresh worker state.
  • Capture output.
  • Auto-surface blocked workers.

So “just looking” is not actually read-only.

Target flow

What should happen

Pi session
→
Owned worker records only
→
tmux / Herdr / lifecycle

Default scope

Only records whose ownerSessionId matches the current Pi session.

Admin scope

Optional explicit global inspection for rescue/debug only.

Roles

What each thing does

Pi session

Owns the workers it creates and sees only its own by default.

Registry

Global storage, not a global permission boundary.

Watcher

Refreshes only owned workers.

Herdr

Surfaces only owned workers unless forced explicitly.

What changes

Behavior after the fix

list / status / poll / read

  • Owned workers only.
  • No cross-session auto-surface.
  • No accidental output capture from others.

Mutating tools

  • send / surface / hide / close stay owner-guarded.
  • force=true remains the explicit escape hatch.
Implementation plan

Minimal rollout

1. Filter at source

Add owner-scoped record loading for read/list/status/poll/watch.

2. Make reads pure

Stop side effects in default read/list/status paths.

3. Keep admin escape hatch

Use an explicit flag for global debugging.

4. Update docs

Explain that storage is shared but access is session-scoped.

Outcome

What good looks like

Each Pi session only sees its own workers unless it explicitly asks for global admin visibility.

Safe

No accidental cross-session reads or surfaces.

Predictable

List/read/status do what users expect.

Ownership becomes a real boundary, not just a field in JSON.
